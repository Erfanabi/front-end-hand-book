## What is CSS Grid and how is it different from flexbox?

Picture a newspaper page: a headline across the full width at the top, a narrow side column, a wide main column, and a footer at the bottom. Or a photo gallery with exactly three equal photos per row whose columns line up from row to row. These are **two-dimensional** layouts: rows matter, and so do columns.

Flexbox is one-dimensional. It can lay items out in a row and wrap them, but the second row knows nothing about the first row's columns, so items don't line up vertically. **CSS Grid** was built for this: you define a **grid** of rows and columns and place items into its cells.

There's also an important difference in mindset:

- **Flexbox starts from the content (content-out):** item sizes come from their content, and flexbox just shares the leftover space.
- **Grid starts from the structure (layout-in):** you define the template (columns and rows) first, and the content goes into it.

## Your first grid

```html live
<style>
  .gallery {
    display: grid;                          /* 1. this element is now a grid container */
    grid-template-columns: 1fr 1fr 1fr;     /* 2. three equal columns */
    gap: 10px;                              /* 3. space between cells */
    font: 600 14px system-ui;
  }
  .gallery div { background: #2459e0; color: white; padding: 18px; border-radius: 8px; text-align: center; }
</style>
<div class="gallery">
  <div>1</div><div>2</div><div>3</div>
  <div>4</div><div>5</div><div>6</div>
  <div>7</div>
</div>
```

Three lines gave us a three-column gallery. What happened?

<Steps>
<Step title="The container defined the grid">
`grid-template-columns: 1fr 1fr 1fr` defined three **columns**. The `fr` unit means "one share of the free space" (explained fully below), so the three columns are equal.
</Step>
<Step title="Direct children became grid items">
As in flexbox, only direct children are affected. Each one takes a cell.
</Step>
<Step title="Items were placed automatically">
We never said which item goes where. The **auto-placement** algorithm put items in HTML order, row by row, into the first free cell.
</Step>
<Step title="Rows were created automatically">
We defined no rows. To fit 7 items into 3 columns, the browser created three rows itself (these are called **implicit tracks**). Item 7 sits in the first column of the third row, **aligned** with the columns above — something flexbox can't do.
</Step>
</Steps>

## Grid vocabulary

```text
        column line 1   line 2        line 3        line 4
              │          │             │             │
   row line 1 ┼──────────┼─────────────┼─────────────┼
              │  cell    │             │             │   ← row track
   row line 2 ┼──────────┼─────────────┼─────────────┼
              │          │   grid area (2×2)         │
   row line 3 ┼──────────┤                           │
              │          │                           │
   row line 4 ┼──────────┴─────────────┴─────────────┼
                         ↑ gap (gutter)
```

| Term | Meaning |
| --- | --- |
| Grid container | The element with `display: grid` |
| Grid item | A **direct** child of the container |
| Grid line | The dividing lines; numbered from 1 (and negatively from the end: `-1` is the last line) |
| Track | The space between two adjacent lines: a row or a column |
| Cell | The intersection of one row and one column |
| Area | A rectangle of one or more cells |
| Gap | Space between tracks |

## Defining tracks

```css
.grid {
  display: grid;
  grid-template-columns: 200px 1fr 2fr;   /* three columns */
  grid-template-rows: auto 1fr auto;      /* three rows */
  gap: 1rem 2rem;                         /* row-gap column-gap */
}
```

### The fr unit

`fr (fraction)` is a share of the **remaining space** after fixed tracks and gaps are subtracted.

Example: a 1000px container, `grid-template-columns: 200px 1fr 2fr; column-gap: 20px`

- Fixed space: 200 + 2×20 = 240px
- Remaining: 760px, split into 3 shares → each fr ≈ 253.3px
- Columns: 200px, 253.3px, 506.7px

`fr` differs from percentages: `33%` is of the whole container and ignores gaps, so `repeat(3, 33.33%)` overflows with a gap while `repeat(3, 1fr)` doesn't.

<Callout type="mistake">
`1fr` is really `minmax(auto, 1fr)`: a track **won't shrink below its content's min-content size**. An image or long word widens the column and the columns become unequal. For truly equal columns: `repeat(3, minmax(0, 1fr))`.
</Callout>

### repeat()

```css
grid-template-columns: repeat(4, 1fr);            /* 1fr 1fr 1fr 1fr */
grid-template-columns: repeat(2, 100px 1fr);      /* 100px 1fr 100px 1fr */
grid-template-columns: 250px repeat(3, 1fr);
```

### minmax()

`minmax(min, max)` clamps a track between two sizes:

```css
grid-template-columns: minmax(200px, 300px) 1fr;
grid-template-rows: minmax(100px, auto);  /* at least 100px, grows with content */
```

### Sizing keywords

| Value | Meaning |
| --- | --- |
| `auto` | Content-based, but also absorbs extra space (when there's no fr) |
| `min-content` | The smallest size without overflow (the longest word) |
| `max-content` | The content's size without wrapping |
| `fit-content(300px)` | Like max-content, capped at 300px |

## auto-fill vs auto-fit

The famous **responsive grid without media queries**:

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(220px, 1fr));
  gap: 1rem;
}
```

The browser creates as many columns of at least 220px as fit. The difference between `auto-fill` and `auto-fit` only shows when there are **fewer items than possible columns**:

| | `auto-fill` | `auto-fit` |
| --- | --- | --- |
| Empty tracks | **Kept** (empty space remains) | **Collapsed** to zero |
| 2 items in space for 5 columns | 2 roughly-220px items at the start | 2 items stretched across the full width |
| Use | Uniform grids (galleries) | Items should fill the space |

```html live
<style>
  .g { display: grid; gap: 8px; margin-bottom: 12px; padding: 6px; border: 2px dashed #aaa; }
  .g > div { background: #2a4bd7; color: #fff; padding: 12px; border-radius: 6px; text-align: center; }
  .fill { grid-template-columns: repeat(auto-fill, minmax(90px, 1fr)); }
  .fit  { grid-template-columns: repeat(auto-fit, minmax(90px, 1fr)); }
</style>
<b>auto-fill</b>
<div class="g fill"><div>1</div><div>2</div></div>
<b>auto-fit</b>
<div class="g fit"><div>1</div><div>2</div></div>
```

Using `min(220px, 100%)` inside `minmax` prevents overflow on very narrow screens:

```css
grid-template-columns: repeat(auto-fit, minmax(min(220px, 100%), 1fr));
```

## Placing items

Auto-placement is enough for many jobs, but sometimes you want to say where an item goes or how many cells it spans. For that you think in grid **lines**, not cells.

### By line number

A three-column grid has **four** vertical lines (1 to 4), because lines sit **around** the columns. They can also be counted from the end with negative numbers: `-1` is the last line. `grid-column: start / end` says which line the item starts and ends on:

```text
line:  1          2          3          4
       │ column 1 │ column 2 │ column 3 │
      -4         -3         -2         -1

grid-column: 1 / 3    → from line 1 to line 3 = columns 1 and 2
grid-column: 1 / -1   → from the first to the last line = full width
grid-column: span 2   → two columns, wherever auto-placement puts it
```

```html live
<style>
  .lines { display: grid; grid-template-columns: repeat(3, 1fr); grid-auto-rows: 50px; gap: 6px; font: 600 13px system-ui; }
  .lines div { background: #e9edfc; border: 1px solid #2459e0; border-radius: 6px; display: grid; place-items: center; }
  .wide { grid-column: 1 / -1; background: #2459e0 !important; color: white; }
  .tall { grid-row: span 2; background: #ffd8a8 !important; }
</style>
<div class="lines">
  <div class="wide">grid-column: 1 / -1</div>
  <div class="tall">grid-row: span 2</div>
  <div>b</div><div>c</div><div>d</div><div>e</div>
</div>

```css
.header  { grid-column: 1 / -1; }       /* first line to last line: full width */
.sidebar { grid-column: 1 / 2; grid-row: 2 / 4; }
.feature { grid-column: span 2; }       /* span two columns from wherever auto-placement puts it */
.box     { grid-area: 2 / 1 / 4 / 3; }  /* row-start / col-start / row-end / col-end */
```

### grid-template-areas

The most readable approach: draw the layout as ASCII art.

```css
.page {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header  header"
    "sidebar main"
    "footer  footer";
  min-height: 100dvh;
}
.page > header { grid-area: header; }
.page > nav    { grid-area: sidebar; }
.page > main   { grid-area: main; }
.page > footer { grid-area: footer; }

@media (max-width: 768px) {
  .page {
    grid-template-columns: 1fr;
    grid-template-areas: "header" "main" "sidebar" "footer";
  }
}
```

Rules: each area must be a **rectangle**; `.` is an empty cell; every row string must have the same number of columns.

```html live
<style>
  .page { display: grid; gap: 6px; grid-template-columns: 110px 1fr; grid-template-rows: auto 120px auto;
          grid-template-areas: "header header" "sidebar main" "footer footer"; font: 14px system-ui; }
  .page > * { background: #e9edfc; border: 1px solid #2a4bd7; padding: 8px; border-radius: 6px; }
  header { grid-area: header; } nav { grid-area: sidebar; background: #ffd8a8 !important; }
  main { grid-area: main; } footer { grid-area: footer; }
</style>
<div class="page"><header>header</header><nav>sidebar</nav><main>main</main><footer>footer</footer></div>
```

## Explicit and implicit grids

- **Explicit grid:** tracks you defined with `grid-template-*`.
- **Implicit grid:** when there are more items than cells, or an item is placed outside the grid, the browser adds tracks automatically.

```css
.feed {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* explicit: columns only */
  grid-auto-rows: minmax(150px, auto);   /* size of implicit rows */
  grid-auto-flow: row;                   /* auto-placement direction: row | column | dense */
}
```

| Property | Controls |
| --- | --- |
| `grid-auto-rows` / `grid-auto-columns` | Size of implicit tracks (default `auto`) |
| `grid-auto-flow: row` | Fill row by row (default) |
| `grid-auto-flow: column` | Fill column by column, creating implicit columns |
| `grid-auto-flow: dense` | Backfill holes with later items (visual order ≠ DOM — mind accessibility) |

## Alignment in Grid

| Property | Applies to | Axis |
| --- | --- | --- |
| `justify-items` | All items within their cells | Inline (horizontal) |
| `align-items` | All items within their cells | Block (vertical) |
| `place-items` | Shorthand for both | — |
| `justify-self` / `align-self` | One item | — |
| `justify-content` / `align-content` | The whole grid inside the container (when the grid is smaller) | — |

```css
.center { display: grid; place-items: center; } /* the shortest centring trick */
```

## Subgrid

`subgrid` (Baseline 2023) lets a grid item that is itself a grid **inherit its parent's tracks**. Classic use: cards whose titles, text and buttons line up across neighbouring cards:

```css
.cards { display: grid; grid-template-columns: repeat(3, 1fr); gap: 1rem; }
.card {
  display: grid;
  grid-row: span 3;
  grid-template-rows: subgrid;   /* three rows from the parent: title, text, button */
}
```

## Flexbox vs Grid

| Criterion | Flexbox | Grid |
| --- | --- | --- |
| Dimensions | One (row **or** column) | Two (rows **and** columns) |
| Approach | Content-out: content drives size | Layout-in: structure defined first |
| Alignment across rows | No; each line is independent | Yes; columns line up in every row |
| Overlapping items | Awkward | Easy (several items in one cell) |
| Best for | Navbars, toolbars, tag lists, component internals | Page layouts, galleries, dashboards, two-column forms |
| Responsive without media queries | `flex-wrap` (last row may be uneven) | `auto-fit/minmax` (regular) |

Rule of thumb: **alignment in one direction only → Flexbox. Rows and columns must align together → Grid.** In practice you use both: Grid for the page skeleton, Flexbox inside components.

## Common mistakes

- Using `1fr` and getting unequal columns (use `minmax(0, 1fr)`).
- `repeat(3, 33.33%)` with a gap, causing overflow.
- `auto-fill` when you need `auto-fit` (or vice versa).
- Non-rectangular areas in `grid-template-areas`.
- Reordering visually with `order`, `dense` or areas without regard for DOM order.
- Forgetting that only **direct children** are grid items (fix: `subgrid` or `display: contents`).

## Interview questions

<QA q="Flexbox or Grid? When do you use each?" level="junior" n={1}>
<Answer>

Flexbox for one-dimensional layouts where content drives size (navbars, buttons, tags). Grid for two-dimensional layouts where rows and columns must line up (page layouts, galleries, dashboards).

</Answer>
<Deep>

The fundamental difference is the direction of control: Flexbox works content-out (each line is computed independently) and Grid layout-in (tracks are shared by all items). For a responsive card list, Grid with `auto-fit` produces regular columns, while Flexbox with `wrap` may leave an uneven, stretched last row.

</Deep>
<Mistake>

Saying "Grid replaces Flexbox". Each is the best tool for its own problem.

</Mistake>
<FollowUp>

How would you build the "holy grail" layout with Grid?

</FollowUp>
</QA>

<QA q="What's the difference between `auto-fill` and `auto-fit`?" level="mid" n={2}>
<Answer>

Both create as many tracks as fit. When there are fewer items than tracks, `auto-fill` keeps the empty tracks (items stay at their minimum and empty space remains), while `auto-fit` collapses empty tracks to zero so `1fr` stretches the items across the full width.

</Answer>
<Deep>

The difference is only visible with `minmax(x, 1fr)` and few items. With a fixed maximum (`minmax(200px, 300px)`) they look the same. The choice is a design decision: a uniform gallery wants `auto-fill`; "two cards that fill the row" wants `auto-fit`.

</Deep>
<Mistake>

Saying there's no difference because most demos with many items look identical.

</Mistake>
<FollowUp>

Why is `minmax(min(250px, 100%), 1fr)` better than `minmax(250px, 1fr)`?

</FollowUp>
</QA>

<QA q="Explain explicit and implicit grids." level="mid" n={3}>
<Answer>

The explicit grid is defined with `grid-template-rows/columns/areas`. When there are more items than cells, or items are placed outside the grid, the browser creates implicit tracks, sized by `grid-auto-rows/columns` (default auto) and directed by `grid-auto-flow`.

</Answer>
<Deep>

The most common pattern: only columns are explicit and all rows are implicit (`grid-auto-rows: minmax(100px, auto)`). Negative line numbers (`-1`) refer to the end of the **explicit** grid only, so `grid-column: 1 / -1` doesn't work in a grid whose columns are implicit.

</Deep>
<Mistake>

Expecting `grid-row: 1 / -1` to span every implicit row.

</Mistake>
<FollowUp>

What accessibility problem does `grid-auto-flow: dense` cause?

</FollowUp>
</QA>

## Recap

<Recap>

- Grid is two-dimensional layout: rows and columns together. Flexbox starts from content, grid from structure.
- `grid-template-columns` and `grid-template-rows` define the explicit grid; extra rows are created implicitly and sized with `grid-auto-rows`.
- `fr` is a share of the space **left over** after fixed tracks and gaps; `1fr` means `minmax(auto, 1fr)`, so write `minmax(0, 1fr)` for truly equal columns.
- `repeat()`, `minmax()` and the keywords `min-content`, `max-content` and `fit-content()` control track sizes.
- `repeat(auto-fit, minmax(220px, 1fr))` makes a responsive grid with no media queries; `auto-fill` keeps empty columns, `auto-fit` collapses them.
- Items are placed by **line** number (`1 / -1` = full width), by `span`, or by name with `grid-template-areas`.
- `place-items: center` is the shortest way to centre; `justify-*` is horizontal, `align-*` vertical.
- `subgrid` lets a nested grid inherit its parent's tracks so the contents of neighbouring cards line up.

</Recap>
